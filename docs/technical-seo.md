# Техническое SEO — Город-Курорт

## Реализовано в исходниках

- Статический HTML каждого маршрута: заголовки, тексты, карточки и ссылки доступны без JS. Поиск и фильтры дополняют уже существующий HTML.
- Уникальные Title/Description/H1, правильная иерархия H2/H3, `lang=ru`, viewport, OG title/description/type/url/image/locale, Twitter card, favicon.
- Хлебные крошки и JSON-LD: Organization, WebSite, WebPage/CollectionPage/ContactPage/AboutPage, BreadcrumbList, ItemList; на карточках Service без вымышленных Offer, рейтингов и наличия.
- Review: `noindex,follow` на всех страницах; canonical отсутствует намеренно, плановый адрес показан в SEO-паспорте. `robots.txt` разрешает обход, чтобы робот видел noindex. Пустой sitemap не объявляется в robots. Это не авторизация.
- Production после разрешения в конфигурации: абсолютный self-canonical, sitemap только для `publishReady=true`; служебные страницы noindex, SEO-карта и экспорт исключены из публичной сборки.
- WebP, собственные локальные файлы изображений, width/height, lazy-loading ниже первого экрана, приоритет первой фотографии. Декоративные изображения имеют пустой alt, содержательные — осмысленный.
- Настоящая страница 404 и HTTP 404 в dev-сервере; на целевом сервере требуется проверить конфигурацию.
- SEO-инспектор сверяет фактические DOM-поля с планом, показывает ключи и нерешённые вопросы. Он не проверяет индексацию и не ставит отметку о готовности серверу.

## Требования на хостинге

1. Один основной хост: `https://gorod-kurort.com`. HTTP и www — 301 сразу на итоговый HTTPS URL. Не создавать цепочки. Сохранять query-параметры, кроме осознанной нормализации.
2. Один формат завершающего `/`. При сохранении адресов проверить существующий формат и сделать 301 варианта. Сейчас в проекте используется `/` в конце страниц.
3. Проверить код 200 для рабочих страниц, 301 только для реальных замен, 404/410 для отсутствующих. Не отвечать главной страницей с 200 на любой неизвестный URL.
4. Переносить старые страницы по карте «старый → новый» на ближайший эквивалент по смыслу. До запуска нужен полный инвентарь старого сайта. Пагинацию и важные карточки сохранить или корректно перенести.
5. Sitemap: только абсолютные canonical URL с 200, разрешённые к индексации; без поиска, корзины, технических страниц, параметров и пустых подборок. `lastmod` только при реальном содержательном изменении, не каждый build.
6. Robots: не блокировать страницу, где робот должен прочитать noindex. Не использовать `Noindex:` в robots. Preview защищать авторизацией, если требуется ограничить доступ.
7. Поиск, корзина, checkout, личный кабинет и случайные фильтры — noindex. UTM не создаёт новую страницу: canonical на чистый адрес. При будущем фильтре с отдельным полезным спросом — ручная посадочная, уникальный контент и разрешение на индекс.
8. При росте каталога пагинация с обычными ссылками `<a href>`, своим URL и self-canonical каждой страницы. Не каноникалить все страницы на первую и не оставлять навигацию только кнопкой JS.
9. Пустые или очень похожие категории не индексировать. Пример — бункер Сталина с одной карточкой: объединить либо расширить подтверждёнными разными программами.
10. Метаданные основного домена и внутренних ссылок должны совпадать. BASE_PATH используется только для предпросмотра на GitHub Pages, не для основного сайта.

## Разметка и контент

- Organization: подтвердить официальное наименование, телефон/email, адрес и реквизиты. Не придумывать рейтинг, количество лет, лицензии и реестровый номер.
- Service в текущем прототипе описывает услугу без обещания расширенного сниппета. Полную модель продажи билетов выбирать по фактической интеграции.
- Event использовать только для конкретного события с действительными startDate/endDate/timezone/location/статусом и стабильным URL экземпляра. Категория, крыша и произвольный повторяющийся тур не получают фиктивную Event-разметку.
- Offer добавлять только после подключения реальных тарифов, валюты RUB, наличия, URL и условий. Никаких «от 0 ₽».
- FAQ полезен посетителю только с согласованными ответами. Не добавлять выдуманные условия возврата, возраст и бесплатность. Не обещать FAQ rich result.
- Отзывы: подключить официально доступный виджет/источник Яндекс Карт после получения карточки организации. Не копировать произвольные рейтинги и не помечать их собственным AggregateRating без проверки правил.
- Оригинальные фотографии проверены визуально и взяты из галерей сайта клиента; источники сохранены. Подтвердить права на дальнейшее использование.

## Конверсия и измерения

- Рабочая цепочка: программа → дата/состав → фактическая цена → заказ → платёж → подтверждение → уведомление накануне. В прототипе её заменяет честно обозначенный план поездки и черновик обращения.
- Подключить CRM/телефонию, Яндекс Метрику и идентификаторы источников после определения схемы обработки персональных данных. События: просмотр программы, выбор даты, добавление, начало оформления, успешный платёж, подтверждённая заявка, целевой звонок. Срабатывание клика не равно реальной продаже.
- Не передавать телефоны, email, ФИО и текст заявки в URL или аналитику. Дедуплицировать отправку, оплату и повторные webhook.
- Проверить LCP/INP/CLS на реальном хостинге и мобильном устройстве; численные результаты пока не измерены. Оптимизировать реальные узкие места после Lighthouse и полевых данных. Не объявлять 100/100 без измерения.
